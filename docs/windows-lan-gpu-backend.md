# Windows LAN GPU Scanner test mode

This runbook is for an isolated development setup in which one Windows machine
runs both the GPU Scanner backend and a local Wrangler Worker. An iPhone or
another LAN client talks only to Wrangler:

```text
iPhone / test client
  -> http://<Windows-private-LAN-IP>:8787
  -> local Wrangler Worker
  -> http://127.0.0.1:8080
  -> Python GPU Scanner
```

This procedure never deploys a Worker and never redirects production. The
Python port must remain loopback-only. The local Worker port is the only port
opened to the private LAN.

The local and production Scanner contracts are intentionally identical:

- Python Backend/RunPod performs SAM3 polaroid extraction only and returns only
  clean `polaroid` results.
- Wrangler/Cloudflare Worker calls Qwen only for an exact single-result
  `GET ...?date_annotation=1` request and returns date/bbox response headers.
- The Worker never draws the bbox, modifies the result body, or stores a
  marked-up image.
- Encoder inference, Idol candidate selection, prototype comparison, and the
  `unassigned` choice belong to iOS. No candidate, prototype, Pattern ID, or ink
  result crosses this backend path.

## 1. Preconditions

Use:

- Windows 10 or 11, 64-bit, with PowerShell 7 or Windows PowerShell 5.1.
- An NVIDIA GPU and a current driver supported by a CUDA-enabled PyTorch build.
- 64-bit Python 3.11.
- Node.js 20 or 22 LTS and npm.
- Git.
- Enough free GPU memory and disk for SAM3. There is no guaranteed minimum in
  this repository; verify the target GPU with the actual model before testing.
- A private/trusted LAN. Do not use a public Wi-Fi profile.
- Optional handwritten-date testing: local access to the existing Qwen-compatible
  service and its HTTPS base URL/API key. Keep both out of Git and command output.

Open PowerShell at the repository root and confirm the checkout and existing
work before changing local configuration:

```powershell
git status --short --branch
git branch --show-current
```

Remain on `main`. Do not clean or reset existing changes.

## 2. Create Python environment and prepare the GPU

Create and activate a repository-local virtual environment:

```powershell
py -3.11 -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

Use the command generated by the official PyTorch “Start Locally” selector for
the installed driver/CUDA combination. Run it before the project requirements,
so the unpinned `torch` requirement is already satisfied:

```powershell
# Replace cuXXX with the index selected at https://pytorch.org/get-started/locally/
python -m pip install torch --index-url https://download.pytorch.org/whl/cuXXX
python -m pip install -r backend\requirements.txt
```

Verify that PyTorch sees CUDA. Stop if this prints `False`:

```powershell
nvidia-smi
python -c "import torch; print('cuda_available=', torch.cuda.is_available()); print('device_count=', torch.cuda.device_count()); print('torch_cuda=', torch.version.cuda)"
```

The backend downloads `facebook/sam3` through ModelScope into
`.\sam3_model\facebook\sam3`. Confirm that the model license and network policy
allow the download, then prepare it from the repository root:

```powershell
python -c "from modelscope import snapshot_download; snapshot_download('facebook/sam3', cache_dir='./sam3_model'); print('model_ready')"
Test-Path .\sam3_model\facebook\sam3
```

Do not continue until the final command returns `True`.

## 3. Start the Python backend on loopback only

Use a first PowerShell window from the repository root:

```powershell
.\.venv\Scripts\Activate.ps1
$env:CHEKINANA_TRUST_LOOPBACK_PROXY = "true"
$env:HOST = "127.0.0.1"
$env:PORT = "8080"
$env:THREADS = "6"
python backend\app.py
```

These settings are mandatory:

- `CHEKINANA_TRUST_LOOPBACK_PROXY` must be exactly `true`.
- `HOST` must be exactly `127.0.0.1`.
- Never use `0.0.0.0` or the LAN address for the Python backend.
- The backend trusts only the actual IPv4 loopback peer. It does not trust
  `X-Forwarded-For`, `CF-Connecting-IP`, or another request header for bypass.

The process starts listening before it loads SAM3. Wait for the SAM3-ready log,
then check the loopback health route from a second PowerShell window:

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/health" -TimeoutSec 10
```

Do not expose port 8080 in Windows Firewall.

## 4. Configure local Wrangler secrets

From the repository root, install the Worker dependencies and verify Wrangler:

```powershell
Set-Location .\cloudflare-worker
npm ci
npx wrangler@latest --version
```

Create `cloudflare-worker\.dev.vars`. It is ignored by Git. Use placeholders
first; never commit real values:

```dotenv
CHEKINANA_SCANNER_LOCAL_MODE="true"
CHEKINANA_SCANNER_LOCAL_UPSTREAM="http://127.0.0.1:8080"
CHEKINANA_SCANNER_LOCAL_TOKEN="<random-local-token>"
CHEKI_DATE_QWEN_API_KEY="<optional-local-secret>"
CHEKI_DATE_QWEN_BASE_URL="<optional-private-https-base-url>"
```

Generate a 32-byte local Scanner token with APIs available in Windows
PowerShell 5.1, without printing it, then write the file. Replace the two Qwen
placeholders locally only when date recognition is needed:

```powershell
$TokenBytes = New-Object byte[] 32
$TokenGenerator = [Security.Cryptography.RandomNumberGenerator]::Create()
try {
  $TokenGenerator.GetBytes($TokenBytes)
} finally {
  $TokenGenerator.Dispose()
}
$LocalScannerToken = -join ($TokenBytes | ForEach-Object { $_.ToString("x2") })

$DevVars = @"
CHEKINANA_SCANNER_LOCAL_MODE="true"
CHEKINANA_SCANNER_LOCAL_UPSTREAM="http://127.0.0.1:8080"
CHEKINANA_SCANNER_LOCAL_TOKEN="$LocalScannerToken"
CHEKI_DATE_QWEN_API_KEY="<optional-local-secret>"
CHEKI_DATE_QWEN_BASE_URL="<optional-private-https-base-url>"
"@
[IO.File]::WriteAllText(
    (Join-Path (Get-Location) ".dev.vars"),
    $DevVars,
    [Text.UTF8Encoding]::new($false)
)
```

The Qwen base must be HTTPS and must not contain userinfo, a query, or a
fragment. Do not use `wrangler secret put` for this local-only session, because
that changes remote state.

## 5. Start Wrangler on the private LAN

Keep the backend running. In the Worker PowerShell window:

```powershell
npx wrangler@latest dev --local --ip 0.0.0.0 --port 8787
```

Confirm Wrangler reports the three local Scanner variables and the Qwen values
when configured. Date annotation has no dedicated rate-limiter binding.

Wrangler may listen on all interfaces; the Python backend must still listen
only on `127.0.0.1:8080`.

## 6. Open only the Worker firewall port

Run an elevated PowerShell window. Restrict the rule to the Private profile and
local subnet:

```powershell
New-NetFirewallRule `
  -DisplayName "Chekinana Wrangler LAN 8787" `
  -Direction Inbound `
  -Action Allow `
  -Protocol TCP `
  -LocalPort 8787 `
  -Profile Private `
  -RemoteAddress LocalSubnet
```

Find the active private IPv4 address:

```powershell
$LanIp = Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object {
    $_.InterfaceOperationalStatus -eq "Up" -and
    $_.IPAddress -notlike "127.*" -and
    $_.IPAddress -notlike "169.254.*"
  } |
  Sort-Object InterfaceMetric |
  Select-Object -First 1 -ExpandProperty IPAddress

if (-not $LanIp) { throw "No active private IPv4 address found" }
$WorkerBase = "http://${LanIp}:8787"
```

Do not print `$LocalScannerToken`. If a new PowerShell window needs it, read the
value from `.dev.vars` into memory without echoing:

```powershell
$LocalScannerToken = (
  Get-Content .\cloudflare-worker\.dev.vars |
  Where-Object { $_ -like "CHEKINANA_SCANNER_LOCAL_TOKEN=*" } |
  Select-Object -First 1
).Split("=", 2)[1].Trim().Trim('"')
```

## 7. Health and isolation checks

The Worker requires the local token even though the backend health route itself
is public:

```powershell
$Headers = @{ "X-Cheki-Token" = $LocalScannerToken }
Invoke-RestMethod -Uri "$WorkerBase/api/health" -Headers $Headers -TimeoutSec 10
```

An incorrect token must return HTTP 401 and must not contact Python:

```powershell
try {
  Invoke-WebRequest `
    -Uri "$WorkerBase/api/health" `
    -Headers @{ "X-Cheki-Token" = "intentionally-wrong-token-value" } `
    -TimeoutSec 10
  throw "Expected HTTP 401"
} catch {
  if ($_.Exception.Response.StatusCode.value__ -ne 401) { throw }
}
```

The LAN address must not expose the Python port:

```powershell
$BackendLanProbe = Test-NetConnection -ComputerName $LanIp -Port 8080 -WarningAction SilentlyContinue
if ($BackendLanProbe.TcpTestSucceeded) {
  throw "Unsafe: Python backend is reachable on the LAN"
}
```

In local mode the Worker removes client-supplied forwarding headers before
calling Python. Python uses the actual loopback peer for allowlisting and upload
rate limiting. Rotating `Forwarded`, `X-Forwarded-For`, `X-Real-IP`, or
Cloudflare-style headers cannot influence Python's client identity. Date
annotation has no dedicated frequency limit but remains protected by the
Scanner token.

## 8. Run a complete ScanCheki test

Choose a local JPG/PNG/WebP/HEIC supported by the backend and an output folder:

```powershell
$ImagePath = (Resolve-Path "C:\path\to\scan-input.jpg").Path
$OutputDir = Join-Path $env:TEMP "chekinana-lan-scan"
New-Item -ItemType Directory -Force -Path $OutputDir | Out-Null
```

Submit through Wrangler. The token is supplied only in the header; Wrangler
also removes an iOS-compatible multipart `token` field if one is present:

```powershell
$SubmitRaw = curl.exe --silent --show-error --fail-with-body `
  -H "X-Cheki-Token: $LocalScannerToken" `
  -F "image=@$ImagePath" `
  -F "wb=1" `
  "$WorkerBase/api/process"
if ($LASTEXITCODE -ne 0) { throw "Scan submit failed" }

$Submit = $SubmitRaw | ConvertFrom-Json
$TaskId = $Submit.task_id
if (-not $TaskId) { throw "Scanner returned no task ID" }
```

Poll without printing or persisting the task ID:

```powershell
$Status = $null
for ($Attempt = 0; $Attempt -lt 180; $Attempt++) {
  $Status = Invoke-RestMethod `
    -Uri "$WorkerBase/api/status/$TaskId" `
    -Headers $Headers `
    -TimeoutSec 30
  if ($Status.status -in @("done", "failed", "canceled")) { break }
  Start-Sleep -Seconds 2
}

if ($Status.status -ne "done") {
  throw "Scanner did not complete: $($Status.status)"
}
$Polaroids = @($Status.results | Where-Object { $_.type -eq "polaroid" })
if ($Polaroids.Count -eq 0) { throw "No polaroid results returned" }
```

Python appends a result only after its PNG bytes are complete. Any result ID
already listed by a status response can be downloaded safely while that status
is still `processing`; an unpublished ID returns HTTP 202. The example above
waits for `done` only to keep the manual smoke test simple.

Download every returned polaroid. Add `date_annotation=1` only when the Qwen
values are configured:

```powershell
$EnableDateAnnotation = $true
$Index = 0
foreach ($Result in $Polaroids) {
  $Index++
  $Suffix = if ($EnableDateAnnotation) { "?date_annotation=1" } else { "" }
  $ResultUrl = "$WorkerBase/api/result/$TaskId/$($Result.id)$Suffix"
  $ImageOut = Join-Path $OutputDir ("polaroid_{0:D2}.png" -f $Index)
  $HeaderOut = Join-Path $OutputDir ("polaroid_{0:D2}.headers.txt" -f $Index)

  curl.exe --silent --show-error --fail-with-body `
    -D $HeaderOut `
    -H "X-Cheki-Token: $LocalScannerToken" `
    $ResultUrl `
    -o $ImageOut
  if ($LASTEXITCODE -ne 0) { throw "Result download failed" }

  Get-Content $HeaderOut |
    Where-Object { $_ -match "^X-Cheki-Date-(Status|Text|Precision|Bbox|Error):" }
}
```

Expected date outcomes are `detected`, `not_detected`, or `unavailable`. With
valid Qwen configuration, the Worker makes the same single Qwen request and
returns the same date headers as production. It never changes the returned
image bytes.

With `$EnableDateAnnotation = $false`, the download is an ordinary result
request: the Worker must make zero Qwen calls and return no
`X-Cheki-Date-*` headers.

## 9. Point an iOS Debug build at Wrangler

The iPhone and Windows machine must be on the same private LAN. In the ignored
`ios\Chekinana\Config\Secrets.xcconfig`, set:

```xcconfig
CHEKINANA_LOCAL_SCANNER_TOKEN = <same-local-scanner-token>
CHEKINANA_SCANNER_BASE_URL = http:/$()/<Windows-private-LAN-IP>:8787
```

The `$()` form is required because raw `//` starts an xcconfig comment. Use a
Debug build: local HTTP is rejected outside the Debug policy, while leaving
`CHEKINANA_SCANNER_BASE_URL` empty selects `https://api.chekinana.top`.

Grant the App local-network permission when iOS asks. Do not put Qwen secrets,
the Python loopback address, or any production Pod ID into the App.

`CHEKINANA_LOCAL_SCANNER_TOKEN` is the iOS Debug build setting. The Wrangler
environment intentionally uses the distinct server-side name
`CHEKINANA_SCANNER_LOCAL_TOKEN`; both values must match for this local session.

## 10. Stop and clean up

Press `Ctrl+C` in the Wrangler window, then in the Python backend window.

Remove the firewall rule from an elevated PowerShell:

```powershell
Remove-NetFirewallRule -DisplayName "Chekinana Wrangler LAN 8787"
```

Remove only the local secret file when the session is finished:

```powershell
Remove-Item -LiteralPath .\cloudflare-worker\.dev.vars -Force
Remove-Item Env:CHEKINANA_TRUST_LOOPBACK_PROXY -ErrorAction SilentlyContinue
Remove-Item Env:HOST -ErrorAction SilentlyContinue
Remove-Item Env:PORT -ErrorAction SilentlyContinue
Remove-Item Env:THREADS -ErrorAction SilentlyContinue
```

The ignored `.venv`, `.wrangler`, and `sam3_model` directories may be retained
for later tests. Delete them only after checking the exact path and deciding the
download/cache is no longer needed.

## 11. Troubleshooting

- `503 local_scanner_configuration_invalid`: one local Worker setting is
  missing, conflicting, or invalid. Use exact lowercase `true`, a URL shaped
  exactly like `http://127.0.0.1:<port>`, and a 16–256 character URL-safe token.
- `401 Token 无效或已过期`: the request header does not exactly match
  `CHEKINANA_SCANNER_LOCAL_TOKEN`. Query/body tokens never authenticate local
  mode.
- `502 local_scanner_upstream_unavailable`: Wrangler could not reach the local
  backend; confirm the backend process and loopback port.
- Backend exits with `Loopback proxy mode requires HOST=127.0.0.1`: correct the
  binding. Never weaken it for LAN testing.
- `cuda_available=False`: install a compatible NVIDIA driver and CUDA-enabled
  PyTorch wheel; do not continue on an unintended CPU fallback.
- SAM3 load failure: run from the repository root and confirm
  `.\sam3_model\facebook\sam3` exists.
- `service_unavailable`: Qwen local secrets are absent or invalid.
- `qwen_timeout`, `qwen_unavailable`, or `invalid_model_output`: inspect only
  the fixed code and local service health; do not log model bodies or secrets.
- iOS cannot connect: confirm the Private firewall rule, LAN IP, Debug build,
  xcconfig slash escaping, local-network permission, and same Wi-Fi/LAN.

## Security red lines

- Never deploy with any `CHEKINANA_SCANNER_LOCAL_*` value.
- Never bind Python to `0.0.0.0`, the LAN IP, or a public interface in trusted
  loopback mode.
- Never open port 8080 in Windows Firewall.
- Never accept an upstream URL from a request.
- Never commit `.dev.vars`, local tokens, Qwen secrets, private endpoints, Pod
  IDs, response cookies, or task/result identifiers.
- Never run `wrangler deploy`, `wrangler secret put`, or `wrangler dev --remote`
  as part of this local procedure.
